# บัญชีเสนอในนาม PM

> เจ้าของสั่ง 2026-09-28 · mockup ที่ยืนยันแล้ว: `mockups/customer-quote-company.html` (5174)
> gate: `npm run diag:customer-quote-company`

## 1. โจทย์

ตั้งค่า **รายบริษัทลูกค้า** ได้ว่า "บริษัทนี้เสนอราคาในนาม PM เท่านั้น" แล้วระบบรู้เองอัตโนมัติ ทั้งจาก LINE และหน้าเว็บ ⇒
ทุกสินค้าของชุดนั้นออกเป็น **ใบ Primus (PM) ใบเดียว** เลข QP ไม่แยกใบ Themtech

### สิ่งที่เจ้าของเคาะ (2026-09-28)

| ข้อ | คำตอบ |
| --- | --- |
| Odoo ฝั่ง PM ขายสินค้าของ THT ได้ไหม | **ได้จริง** ⇒ ใบ QP ที่มีสินค้า THT นำเข้าได้ ไฟล์ export ไม่ต้องแก้ |
| ขอบเขตของ "บริษัท" | **เหมือนบัญชีห้ามเสนอราคา** ⇒ ขยายทั้งนิติบุคคล (เลขภาษี/รหัสอ้างอิง/ชื่อ — `db/companyIdentity.ts`) |
| ระดับ | **ทั้งบริษัทเท่านั้น** (ไม่มีระดับผู้ติดต่อ) |
| ใครตั้งได้ | admin · subadmin · approver (`page.quotepm`) |
| กำหนดส่งของใบรวม | ค่าที่นานที่สุดของทุกรายการ (พฤติกรรมเดิมของ `resolveQuotationDeliveryDays`) — **ใช้ได้** |
| ชื่อเมนู | "บัญชีเสนอในนาม PM" |

## 2. โครงสร้าง

```
customer_quote_company (company_id PK, quote_company 'PM', note, created_by, …)   ← ค่าตั้งรายบริษัท
        │  decideForcedQuoteCompany({ customerId, reviseFrom })   ← จุดตัดสินเดียว
        ▼
quotations.quote_company_override ('PM' | 'THT' | NULL)   ← ตรึงลงใบตอนผูกลูกค้า
        │
        ▼  ทุกจุดที่ถาม "ใบนี้บริษัทไหน" อ่านคอลัมน์นี้ก่อน แล้วค่อย resolveQuoteCompany(สินค้ารายการแรก)
```

**ทำไมต้องตรึงลงใบ ไม่ถามตารางตั้งค่าทุกครั้ง** — ระบบไม่เคยเก็บว่าใบเป็นบริษัทไหน มันคำนวณใหม่จากสินค้ารายการแรกทุกครั้ง
(ออกเลข · enrich · หัว PDF ร่าง · Flex · ค่าขนส่ง) ⇒ ใบรวมที่ขึ้นต้นด้วยสินค้า THT จะได้เลข QT ถ้าไม่มีคอลัมน์นี้ ·
และแก้ค่าตั้งทีหลังแล้วใบที่มีอยู่ต้องไม่สลับหัว

**NULL = แบ่งตามสินค้าเหมือนเดิมทุกไบต์** — ใบเก่าทุกใบ · ลูกค้าที่ไม่ได้ตั้ง ⇒ ไม่มี backfill

### ตัดสินที่ไหน

| ทางเข้า | จุด |
| --- | --- |
| สร้างร่างตอนรู้ลูกค้าแล้ว (หน้าเว็บ · LIFF · แก้ใบเดิม · LINE ที่ผูกลูกค้าได้ทันที) | `insertDraftQuotations` (ข้อ 2.5 — ย้ายการแบ่งใบลงไปหลังอ่าน `revise_from`) |
| LINE ที่แบ่งไปก่อนตอนยังไม่รู้ลูกค้า (`pending_company`) | `updateQuotationCustomerSnapshot` → `applyForcedQuoteCompany` รวมใบ: ใบเป้าหมาย = ใบที่สินค้ารายการแรกตกบริษัทที่ตั้ง · ใบอื่น **DELETE** (ร่างไม่มีเลข = ลบ) · transaction เดียว |
| LIFF เปลี่ยนลูกค้าของร่าง (`PUT /api/quotation/:id`) | ตรึงใหม่เฉพาะตอนลูกค้าเปลี่ยน · ใบเดียว ไม่รวมกับใบพี่น้อง |
| พรีวิวหน้าเว็บ | `previewDraftInternal` เรียก `decideForcedQuoteCompany` ตัวเดียวกัน (รับ `revise_from` มาด้วย) ⇒ จอ = สิ่งที่ /drafts บันทึก |

### แก้ใบเดิม = ยึดใบต้นทาง

เลข revision ยึดคำนำหน้าของเลขเดิม (`QT-…-01`) ⇒ ถ้าร่าง revise ถูกบังคับตามค่าตั้ง **ปัจจุบัน** ใบ THT เดิมจะได้หัว Primus บนเลข QT
⇒ `decideForcedQuoteCompany({ reviseFrom })` อ่าน `quote_company_override` ของใบต้นทางแทน · ใบต้นทางออกก่อนตั้ง (NULL) = แบ่งเหมือนเดิม

### ล้มแล้วปล่อยผ่าน

นี่ไม่ใช่ด่านกฎ ⇒ ถามตารางไม่สำเร็จ = แบ่งตามสินค้าเหมือนเดิม (ได้สองใบ — ผิดแบบเห็นได้ ไม่มีของหลุดถึงลูกค้าที่ไม่ควรได้)
ต่างจากบัญชีห้ามเสนอราคาที่ fail-closed

ด่านนับจุดเรียก `resolveQuoteCompany(` ต่อไฟล์ ⇒ ใครเพิ่มจุดใหม่ ด่านล้มให้ตัดสินว่าต้องเคารพค่าที่ตรึงไหม

## 5. ข้อจำกัดที่รู้แล้ว

- ร่างที่ค้างอยู่ตอนตั้งค่า (รวมใบรออนุมัติ) ไม่เปลี่ยน · มีผลกับใบที่สร้าง/ผูกลูกค้าหลังตั้งค่า

- ถอดค่าออก / เปลี่ยนลูกค้าเป็นรายที่ไม่ได้ตั้ง → ร่างที่ตรึงไว้แล้วไม่แยกกลับ
