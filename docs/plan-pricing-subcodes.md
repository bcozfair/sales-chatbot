### 1.2 ตัวเลขมีตารางรองรับ แต่ "ตัวอักษร" ไม่มี

ตัวเลขในรหัส (แกน · ความยาว · กำลังไฟ · ความยาวสาย) มีตารางราคาหรือสูตรรองรับอยู่แล้วทุกตัว
แต่ **ตัวอักษรท้ายรหัสแทบไม่มีที่ไหนในไฟล์บอกว่าแปลว่าอะไรและคิดเงินเท่าไหร่**

หลักฐานที่ชัดที่สุดอยู่ในชีต TS-14 เอง: ตัวอย่างที่ฝ่ายขายเขียนไว้คือ `TSK-14 6x200+150-BU`
แล้วบรรทัดถัดมาคิดราคาว่า `4000+(3*300)+(1*130) = 5,030` — **ไม่มีบรรทัดไหนคิดค่า `-BU` เลย**
ทั้งที่ชีตเดียวกันมีคอลัมน์ "หัวกระโหลก Blacklite ใหญ่ บวกเพิ่ม 700" อยู่ ⇒ ตัวอักษรกับราคาไม่ได้
ผูกกันไว้ที่ไหน มันอยู่ในหัวคนที่ออกใบ

### 1.3 ต้องตั้งค่ากี่รหัสย่อย — นับจากรหัสจริง 22,061 รหัสในตาราง `products`

| | ชนิดที่ต่างกัน | ครอบคลุม |
| --- | ---: | --- |
| รหัสย่อยในวงเล็บ `( )` | 123 แบบ | **20 ตัวแรก = 96.0%** ของที่ปรากฏทั้งหมด |
| รหัสย่อยต่อท้ายคั่นด้วย `-` | 2,029 แบบ | **30 ตัวแรก = 81.5%** |

รหัสย่อยในวงเล็บที่พบบ่อย: `S4` 4,037 · `S2` 2,831 · `S6` 1,129 · `S3` 902 · `M6` 519 · `M8` 503 ·
`S8` 432 · `S1` 396 · `HPT` 330 · `M10` 238 · `M12` 227
รหัสย่อยต่อท้ายที่พบบ่อย: `U` 2,569 · `BU` 1,856 · `S000` 1,678 · `PU` 781 · `B` 748 · `TU` 702 ·
`TSU` 517 · `N` 391 · `MP` 243 · `PL2` 219 · `KU` 217 · `T` 173

**อ่านตัวเลขสองแถวนี้ให้ถูก:** 2,029 แบบ **ไม่ได้แปลว่าต้องตั้งค่า 2,029 ตัว** — ตั้งค่า 30 ตัวแรกได้
81.5% แล้ว และที่เหลือส่วนใหญ่เป็นรูปแบบเดียวกันที่เปลี่ยนแค่ตัวเลข (`S000` `S001` `S002` …)
ซึ่งตารางรหัสย่อยรับเป็น **แม่แบบเดียว** ได้ (ข้อ 3.2)

### 1.4 สามข้อที่ทำให้ "แปลตัวอักษรเป็นราคา" ต้องระวัง

1. **รหัสย่อยเดียวกันข้ามรุ่นราคาไม่เท่ากัน** — พิสูจน์แล้วจากหน้าแปลน JIS 10K: ชีต `TS-18` คิด
   1" = 650 แต่ชีต `TW` คิด 1" = 800 ⇒ **ตารางรหัสย่อยต้องผูกกับรุ่นก่อน แล้วค่อยตกลงมาที่ค่ากลาง**
2. **รหัสย่อยประกอบกันได้** — รหัสย่อยต่อท้ายที่ลงท้ายด้วย `U` มีเป็นชุด (`U` · `BU` · `PU` · `TU` · `KU` ·
   `TSU` · `KBU` · `2BU` · `EU` · `SU` · `CU`) ดูเหมือนเป็น "ตัวอักษรของหัว + U"
   **แต่ยังไม่มีหลักฐาน** ⇒ ค่าเริ่มต้นต้องเป็น "จับคู่ทั้งรหัสย่อยแบบตรงตัว" เท่านั้น
   จะเปิดโหมดแยกทีละตัวอักษรได้ต่อเมื่อฝ่ายขายยืนยันว่ากติกาคืออะไร
3. **ตัวเลขล้วนในรหัสย่อยต่อท้ายไม่ใช่เรื่องเดียวกันทุกที่** — ของ BH คือแรงดันไฟ (ไม่มีผลกับราคา)
   ของ TS บางรุ่นเป็นจำนวน element ⇒ ความหมายของ "ตัวเลขล้วน" ต้องตั้งรายรุ่นเหมือนรหัสย่อยอื่น

## 2. แบบที่เสนอ — ของใหม่มีชั้นเดียว คือ "ตารางรหัสย่อย"

```
รหัสที่แอดมินพิมพ์
   │
   ├─ ชั้น 1  แม่แบบรหัสของรุ่น (codePattern)   ← ลอกจากหัวตารางในชีต
   │            บอกว่าตัวเลขแต่ละตำแหน่งคืออะไร
   │
   ├─ ชั้น 2  ตารางรหัสย่อย (subCodes)          ← ★ ของใหม่ทั้งหมดอยู่ตรงนี้
   │            บอกว่ารหัสย่อยแต่ละตัวแปลว่าอะไร และทำอะไรกับราคา
   │
   └─ ชั้น 3  สมุดราคาเดิม (ตารางราคาตั้ง + กฎบวกเพิ่ม)  ← ไม่แตะเลยสักบรรทัด
                คิดเงินและคืน "ที่มาของราคา" เหมือนที่ทำอยู่ทุกวันนี้
```

**ทำไมของใหม่ต้องเป็นข้อมูล ไม่ใช่โค้ด:** ราคาและกติกาของร้านเปลี่ยนเองได้ทุกไม่กี่เดือน
ถ้าความหมายของ `-BU` ฝังอยู่ในโค้ด แปลว่าร้านแก้เองไม่ได้ ต้องรอ deploy ทุกครั้ง
(หลักการข้อ 2 ของ `AGENTS.md`) — และนี่คือสิ่งที่หัวหน้าสั่งมาตรง ๆ

### 2.1 ทำไมไม่ให้ AI เดาความหมายของรหัส

ระบบนี้มี LLM อยู่แล้ว และการโยนรหัสให้ LLM ทายว่า `-BU` คืออะไรทำได้ทันที **แต่เลือกไม่ทำ**
ด้วยเหตุผลสามข้อ: ราคาต้องซ้ำได้ทุกครั้งที่กดคำนวณ (LLM ไม่การันตี) · ต้องตอบได้ว่าเลขนี้มาจาก
ไหนตอนลูกค้าทัก (คำตอบ "AI ว่างั้น" ใช้ไม่ได้) · และเส้น LINE มีงบเวลาแค่ 48 วินาทีต่อข้อความ
⇒ AI ช่วยได้ในฐานะ **ตัวเสนอ** ("รหัสย่อยนี้เคยเจอในรุ่นอื่นแปลว่า X จะใช้แบบเดียวกันไหม")
แต่คนเป็นคนกดยืนยัน และสิ่งที่ถูกบันทึกคือคำตอบของคน

## 3. โครงสร้างข้อมูล

### 3.1 แม่แบบรหัสของรุ่น (ชั้น 1)

เก็บในสมุดราคาของรุ่นนั้น ลอกจากหัวตารางในชีตตรง ๆ:

```json
{
  "code": "TS-18",
  "codePattern": "(F_) D1-D2 xL1+L2",
  "codePatternSource": "TS-18!A13 'ราคาตั้ง Standard TS_- 18 (F_) D1-D2 x100+50'"
}
```

ช่องที่แม่แบบรู้จัก: `D` `D1` `D2` `Dai` (ค่าแกน) · `L1` `L2` `W` (ความยาว) ·
`(S_)` `(F_)` (รหัสย่อยในวงเล็บ) · `+nM` (ความยาวสาย) — ที่เหลือคือ "รหัสย่อย" ที่ส่งต่อให้ชั้น 2

### 3.2 ตารางรหัสย่อย (ชั้น 2) — หัวใจของงานนี้

หนึ่งแถว = หนึ่งรหัสย่อยที่แอดมินตั้งค่าไว้:

| ช่อง | คืออะไร | ตัวอย่าง |
| --- | --- | --- |
| **รหัสย่อย** | ตัวอักษรตามที่พิมพ์ในรหัส | `BU` · `MP` · `S###` |
| **แบบจับคู่** | `ตรงตัว` หรือ `แม่แบบ` (`#` = ตัวเลขหนึ่งหลัก) | แม่แบบ → `S###` จับ `S000` `S001` `S002` ได้ทั้งชุด |
| **ใช้กับ** | รุ่นนี้ · ทั้งตระกูล (TS-18 + TS-18S) · ทุกรุ่น | รุ่นนี้ |
| **อ่านว่า** | ข้อความไทยที่จะขึ้นบนจอ | "หัวกระโหลก Blacklite ใหญ่" |
| **ผลกับราคา** | 6 แบบ (ตารางข้างล่าง) | บวกเงินคงที่ |
| **ค่า** | ตัวเลข หรือชื่อค่าที่จะตั้งให้ | 700 |
| **ลำดับ** | ลำดับการคิด เหมือนกฎเดิม (ลำดับมีผลจริงเมื่อมี %) | 35 |
| **สถานะ** | `ใช้งาน` หรือ `ร่าง` (เห็นบนจอแต่ยังไม่คิดเงิน) | ใช้งาน |
| **ใครตั้งค่า / เมื่อไหร่** | ไว้ตอบตอนราคาเพี้ยน | แอดมิน A · 18/09/2026 |

**ผลกับราคา 6 แบบ ครอบคลุมของจริงที่เจอในไฟล์:**

| แบบ | ทำอะไร | ใช้กับรหัสย่อยแบบไหน |
| --- | --- | --- |
| 1. ไม่มีผลกับราคา | อ่านออก บันทึกไว้ แต่ไม่คิดเงิน | `S000` (หมายเลขแบบ) · แรงดันไฟ `240` |
| 2. **ราคาตั้งต้นของตัวเอง** | ทิ้งราคาตั้งจากตาราง แล้วใช้ราคานี้แทน | รุ่นพิเศษที่ราคาไม่อิงตาราง |
| 3. บวกเงินคงที่ | +700 | หัวกระโหลก · ปลั๊ก `MP` |
| 4. บวกเป็นเปอร์เซ็นต์ | +20% ของยอดสะสม | รุ่น C ของ BH |
| 5. บวกตามส่วนที่เกิน | (ค่าที่เกินมาตรฐาน ÷ ช่วง) × ราคา/ช่วง | ความยาวสาย · ความยาวแกน |
| 6. ตั้งค่าให้ช่องใดช่องหนึ่ง | เซ็ตค่าแกน/ขนาด แล้วให้ตารางเดิมคิดต่อ | `(S4)` → เกลียว 1/2" · `(F5)` → หน้าแปลน |

แบบที่ 2 คือ "ราคาตั้งต้น" ที่หัวหน้าสั่งมา · แบบที่ 3–5 คือ "กฎการคำนวณ" ซึ่ง **ใช้โครงเดียวกับ
กฎบวกเพิ่มที่มีอยู่แล้วทุกประการ** ⇒ หน้าจอแก้กฎที่ทำไว้แล้วใช้ต่อได้เลย ไม่ต้องเขียนใหม่

ตัวอย่างหนึ่งแถวในสมุดราคา:

```json
{
  "subCode": "BU",
  "match": "exact",
  "scope": "TS-14",
  "reads": "หัวกระโหลก Blacklite ใหญ่",
  "effect": "flat",
  "amount": 700,
  "order": 35,
  "status": "active",
  "source": "TS-14!O12 'หัวกระโหลก Blackliteใหญ่ บวกเพิ่ม'",
  "by": "แอดมิน A", "at": "2026-09-18"
}
```

### 3.3 ลำดับการค้น (สำคัญ เพราะรหัสย่อยซ้ำข้ามรุ่นได้)

`รุ่นนั้นตรง ๆ` → `ตระกูลเดียวกัน` → `ทุกรุ่น` · และในแต่ละชั้น `ตรงตัว` มาก่อน `แม่แบบ` เสมอ
⇒ ตั้งค่ากลางไว้ได้โดยไม่ต้องกลัวว่ารุ่นที่ราคาต่างจะถูกกลืน

## 4. รหัสหนึ่งรหัสเดินทางยังไง

ใช้รหัสจริงจากหน้าจอ: `BH-01 230x32-240-650W-N-S000`

| ขั้น | ได้อะไร |
| --- | --- |
| 1. ล้างรูปแบบ | ตัดช่องว่าง · เครื่องหมายนิ้วทุกแบบให้เป็นแบบเดียว |
| 2. หาหัวรุ่น | `BH-01` → เจอในสมุดราคา พร้อมแม่แบบรหัสของมัน |
| 3. อ่านตัวเลขตามแม่แบบ | `230x32` = เส้นผ่านศูนย์กลาง 230 × ความกว้าง 32 |
| 4. ค้นตารางรหัสย่อยทีละตัว | `240` → แรงดันไฟ ไม่มีผล · `650W` → กำลังไฟ (รุ่นนี้ไม่คิดตามกำลังไฟ) · `N` → **ยังไม่ได้ตั้งค่า** · `S000` → **ยังไม่ได้ตั้งค่า** |
| 5. คิดราคา | ส่งสเปกเข้า engine เดิม → ได้ราคา + ที่มาทีละบรรทัด |
| 6. รายงาน | ขึ้นราคา + ธงว่า "ยังไม่รวม 2 รหัสย่อย (N · S000)" พร้อมปุ่ม **"+ เพิ่ม N"** / **"+ เพิ่ม S000"** ข้างรหัสย่อยนั้นเลย |

**ปุ่มเพิ่มรหัสย่อยต้องอยู่ตรงจุดที่เจอปัญหา ไม่ใช่ในเมนูตั้งค่า** — คนที่รู้ว่า `N` แปลว่าอะไร
คือคนที่กำลังออกใบอยู่ตอนนั้น ถ้าต้องจำไว้ไปแก้ทีหลัง มันจะไม่ถูกแก้

**และบนปุ่มต้องเขียนรหัสย่อยตัวจริงลงไป (`+ เพิ่ม S000`) ไม่ใช่คำว่า "อันนี้"** — บรรทัดเดียว
มีรหัสย่อยที่อ่านไม่ออกได้หลายตัว ถ้าทุกปุ่มเขียนเหมือนกันหมด คนกดต้องไล่สายตาหาว่าปุ่มไหน
ของตัวไหน · เจ้าของเคาะชื่อปุ่มนี้ 2026-09-18 พร้อมสั่งให้ **เลี่ยงคำว่า "สอน" ทั้งฉบับ**
เพราะงานนี้คือการตั้งค่ารหัสประกอบของสินค้า custom ไม่ใช่การเทรนโมเดล

## 5. หน้าจอ

### 5.1 หน้า "ลองคิดราคา" (มีอยู่แล้ว เพิ่มของเล็กน้อย)

```
┌ พิมพ์รหัสสินค้า ────────────────────────────────────────────────┐
│ [ BH-01 230x32-240-650W-N-S000            ]   [ อ่านรหัส ]      │
│                                                                 │
│ BH-01    อ่านได้         รุ่น BH-01 — Band Heater สแตนเลส+Zinc  │
│ 230x32   อ่านได้         เส้นผ่านศูนย์กลาง 230 mm × กว้าง 32 mm │
│ 240      ไม่มีผลกับราคา  แรงดันไฟ 240 V                         │
│ 650W     ไม่มีผลกับราคา  รุ่นนี้ไม่คิดราคาตามกำลังไฟ            │
│ N        อ่านไม่ออก      ยังไม่ได้ตั้งค่า   [ + เพิ่ม N ]       │
│ S000     อ่านไม่ออก      ยังไม่ได้ตั้งค่า   [ + เพิ่ม S000 ]    │
│                                                                 │
│ ⚠ ราคาข้างล่างยังไม่รวม 2 รหัสย่อยที่อ่านไม่ออก                 │
└─────────────────────────────────────────────────────────────────┘
```

กด **"+ เพิ่ม S000"** → กล่องเดียวจบ: อ่านว่าอะไร · ผลกับราคาแบบไหน · ค่าเท่าไหร่ · ใช้กับรุ่นนี้หรือทุกรุ่น
· กดบันทึกแล้ว **ราคาบนจอคิดใหม่ทันที** ไม่ต้องรีโหลด

### 5.2 หน้า "แก้กฎราคา" (มีอยู่แล้ว เพิ่มแท็บ)

เพิ่มแท็บ **"ตั้งค่ารหัสย่อย"** — ตารางรหัสย่อยทั้งหมดของรุ่นที่เลือก แก้ไข/ปิดชั่วคราว/ลบได้
และมีสองอย่างที่ต้องมีตั้งแต่วันแรก:

* **"รหัสย่อยที่ยังไม่ได้ตั้งค่า"** เรียงตามความถี่ที่เจอจริง — แอดมินไล่เก็บจากบนลงล่างได้
  (วันนี้คือ `U` 2,569 · `BU` 1,856 · `S000` 1,678 …) ⇒ เห็นว่าเหลืออีกกี่ตัวถึงจะครบ
* **ส่งออก/นำเข้า `.xlsx`** ชีตใหม่ชีตเดียวในแม่แบบเดิม — ตั้งค่า 30 ตัวรวดใน Excel เร็วกว่าจิ้มทีละตัว

## 6. กติกาความปลอดภัย (ห้ามตัดออกตอนทำจริง)

1. **รหัสย่อยที่ยังไม่ได้ตั้งค่า ต้องขึ้นเตือนเสมอ ห้ามข้ามเงียบ ๆ** — ราคาที่ตกของไปหนึ่งรหัสย่อย
   หน้าตาเหมือนราคาที่ถูกต้องทุกประการ นี่คือกฎเดียวกับที่ตัวอ่านรหัสวันนี้ยึดอยู่แล้ว
2. **ตั้งค่าผิดก็ราคาผิดเงียบได้เหมือนกัน** ⇒ ทุกแถวต้องมี "ใครตั้งค่า เมื่อไหร่" และแก้แล้วต้องเห็นว่า
   ราคาของเคสทดสอบขยับไปเท่าไหร่ (หน้าแก้กฎทำแบบนี้อยู่แล้ว)
3. **รหัสย่อยที่ตั้งค่าเองต้องแยกจากของที่มาจากไฟล์ราคา** — เหมือนที่กฎที่เพิ่มเองถูกทำเครื่องหมาย
   `custom` ไว้ ไม่งั้นไฟล์ราคารอบหน้ามาจะทับของที่แอดมินตั้งค่าไว้ทั้งหมด
4. **ราคาใน Odoo ไม่ใช่เฉลย** — วัดแล้ว 2026-09-18: รหัสที่สเปกตรง Standard เป๊ะ 28 รหัส
   ต่างจากชีต 16 รหัส ทั้งสองทิศทาง ⇒ ห้ามตั้งค่ารหัสย่อยเพื่อ "ดัดราคาให้ตรง Odoo"
5. **ของที่ยังไม่รู้ ต้องไม่กลายเป็นของที่เดาเอง** — โหมด "แยกรหัสย่อยทีละตัวอักษร" (เช่น `KBU` =
   `K`+`B`+`U`) ปิดไว้ก่อน จนกว่าฝ่ายขายจะยืนยันกติกา

## 8. คำถามที่ต้องได้คำตอบก่อน (แยกว่าใครตอบ)

**ฝ่ายขาย / ผลิต 2 ตอบได้เลย — ไม่ต้องรอหัวหน้า:**

1. `-U` (2,569 รหัส) · `-BU` (1,856) · `-PU` (781) · `-B` (748) · `-TU` (702) แปลว่าอะไร
   และคิดเงินเพิ่มไหม
2. `S000` / `S001` / `S002` (1,678+) คือหมายเลขแบบใช่ไหม และมีผลกับราคาหรือไม่
3. ตัวอักษรที่ลงท้ายด้วย `U` เป็น "คำประกอบ" (หัว + U) หรือเป็นคำเดี่ยวที่บังเอิญคล้ายกัน
4. เกลียวมิล `(M6) (M8) (M10) (M12)` (1,487 รหัส) ราคาคิดยังไง — ไฟล์ราคาไม่มีตารางของมันเลย
5. `(HPT)` (330 รหัส) คืออะไร เป็นราคาตั้งคนละชุดหรือเป็นส่วนบวกเพิ่ม

**หัวหน้าตัดสิน:**

6. ใครมีสิทธิ์เพิ่ม/แก้รหัสย่อย — แอดมินทุกคน หรือเฉพาะคนที่ตั้งราคาได้
7. ตั้งค่าแล้วมีผลทันที หรือต้องมีคนอนุมัติก่อน
8. ไฟล์ราคารอบใหม่มา จะทับรหัสย่อยที่ตั้งค่าเองไว้ยังไง

## 9. ของที่แบบนี้ **ไม่** ทำ

* ไม่แตะวิธีคิดราคาเดิมสักบรรทัด — ตารางราคาตั้ง · กฎบวกเพิ่ม · ลำดับการคิด เหมือนเดิมทุกอย่าง
* ไม่เดาความหมายของรหัสย่อยที่ยังไม่ได้ตั้งค่า
* ไม่ทำให้รหัสที่อ่านไม่ครบ "ดูเหมือนคิดราคาครบ"
* ไม่ยุ่งกับใบเสนอราคาจริง ใบที่ออกจาก LINE และหน้าเว็บทุกวันนี้ไม่ขยับ
