แอดมินพิมพ์รหัสสินค้าสั่งทำ (`TSK-14 6x200+150-BU`) แล้วได้ราคาพร้อมที่มาของทุกบาท ·
ตัวอักษรที่ระบบยังไม่รู้จักมีปุ่มให้ตั้งค่าเองตรงนั้น ไม่ต้องรอแก้โปรแกรม

**เจ้าของสั่ง 2026-09-18:** เอาของที่ทำไว้เข้าหน้าแอดมินจริง เพื่อให้คนที่ล็อกอินแล้ว
เท่านั้นเข้าไปทดลองใช้ได้ — **เฟสแรกยังไม่ต่อกับใบเสนอราคา คิดราคาให้ดูอย่างเดียว**
และต้องถอดออก/แก้เพิ่มได้ทุกเมื่อระหว่างที่ดีไซน์ยังไม่นิ่ง

**เจ้าของสั่ง 2026-09-21:** เลิกทำงานใน `prototypes/` — หน้า "คิดราคาสินค้า" มีจริงแล้ว
⇒ โฟลเดอร์นั้นถูกลบทิ้งทั้งก้อน ของที่ยังจำเป็นย้ายมาอยู่ในระบบจริงทั้งหมด:

## สมุดราคาอยู่ที่ไหน และทำไมต้องคิดที่เซิร์ฟเวอร์

**ในฐานข้อมูล** (ตั้งแต่ 2026-09-23 · แบบเต็มอยู่ที่ `docs/plan-pricebook-db.md`) — สามตาราง:

| ตาราง | หนึ่งแถว = |
| --- | --- |
| `pricing_models` | หนึ่งรุ่นของเล่มปัจจุบัน (`spec` = `PriceModel` ทั้งก้อน · **`json` ไม่ใช่ `jsonb`** เพราะ jsonb สลับลำดับคีย์ แล้วแม่แบบ .xlsx เรียงใหม่ 16 จาก 22 ชีต) |
| `pricing_model_history` | สเปกของรุ่นหนึ่งหลังการบันทึกครั้งหนึ่ง — **เขียนต่อท้ายอย่างเดียว** เก็บตลอดไป |
| `pricing_book_revisions` | การบันทึกหนึ่งครั้ง (เล่มแรก · อัปแม่แบบ · แก้ทีละรุ่น · ย้อน) + ฟิลด์ระดับเล่ม + ชื่อ/sha256 ของไฟล์ที่ใช้ |

ยุคก่อนหน้าเป็นไฟล์ `pricebook/book.json` ในคอนเทนเนอร์ที่ไม่มี volume ⇒ **rebuild ทุกครั้งทิ้งราคาที่แอดมิน
แก้พร้อมเล่มสำรองทั้งหมด** และสำรองตีสามไม่เคยถ่ายมันไป · ตอนนี้ราคาเข้า dump ตีสามเองอัตโนมัติ
(⚠️ ⇒ `db:restore` พาราคาย้อนไปด้วย)

**เล่มแรกของฐานมาทาง CLI เท่านั้น** (หน้าจอบูตเล่มแรกไม่ได้ เพราะแม่แบบเกิดจากเล่มที่มีอยู่):

```bash
npx tsx scripts/pricebook/importer.ts --data <โฟลเดอร์ Excel>                    # รายงานอย่างเดียว ไม่เขียนอะไร
npx tsx scripts/pricebook/importer.ts --data <dir> --apply --by <username>       # เล่มแรก
npx tsx scripts/pricebook/importer.ts --data <dir> --apply --replace-all --by …  # แทนทั้งเล่ม (ย้อนได้จากจอ)
npx tsx scripts/pricebook/importer.ts --from-json pricebook/book.json --apply    # ย้ายเล่มของยุคไฟล์เข้าฐาน
npm run diag:pricing && npm run diag:pricing-coverage
```

`--data` **ไม่มีค่าเริ่มต้นโดยตั้งใจ** (ยุคไฟล์ตั้งต้นที่ `data/` ซึ่งถูกเสิร์ฟออกเว็บ) · บน PMSV ไฟล์ Excel อยู่ที่
`backup/` ของ host ซึ่ง `.dockerignore` กันไว้ ⇒ นำเข้าด้วยคอนเทนเนอร์ครั้งเดียว — runbook ใน `DEPLOY.md` ขั้น 4.11

**เครื่องมืออื่นของสมุดราคา (`scripts/pricebook/`):**

```bash
npm run pricebook:xlsx -- export              # แม่แบบกฎราคา .xlsx → โฟลเดอร์ชั่วคราวของเครื่อง (หรือ --out)
npm run pricebook:xlsx -- odoo                # ตารางราคาสำหรับนำเข้า Odoo (ทางเดียว)
npm run pricebook:xlsx -- import "<ไฟล์>.xlsx"  # ตรวจไฟล์อย่างเดียว (`--save` ถูกถอดแล้ว — บันทึกผ่านจอ)
npm run pricebook:calc -- --code "TSK-04(S2)6x300+3M"   # ลองคิดราคาจากบรรทัดคำสั่ง
npm run pricebook:calc -- --subcodes
```

ทุกคำสั่งใช้เล่มปัจจุบันในฐาน · `--book <ไฟล์.json>` หรือ `--data <dir>` ใช้เล่มอื่นแทนได้
(`scripts/pricebook/bookSource.ts` — ที่เดียวที่ CLI และด่านหาเล่ม และพิมพ์บรรทัดแรกเสมอว่าใช้เล่มไหน)

ตัวนำเข้าอ่านไฟล์ Excel ผ่าน **ไฟล์ map เขียนมือ** ใน `scripts/pricebook/maps/` — หนึ่งไฟล์
ต่อหนึ่งตารางราคา บอกว่าตารางอยู่เซลล์ไหน **ไม่ใช้ auto-detect โดยตั้งใจ** เพราะ 30 ชีตวางหัวตาราง
คนละแบบ ⇒ เดาผิดเงียบ ๆ แล้วไม่มีใครรู้จนของหลุดถึงลูกค้า

### สามที่ที่ห้ามวางสมุดราคา — ทั้งสามถูกเสิร์ฟออกเว็บโดยไม่มีการตรวจสิทธิ์

1. **`public/`** — `express.static` ที่ `index.ts`
2. **`data/`** — `express.static('/data')` ที่ `index.ts` (ไฟล์ `.xlsx` ต้นทางก็ห้ามไปไว้ที่นั่น
   ด้วยเหตุผลเดียวกัน — `.gitignore` กับ `.dockerignore` กัน `*.xlsx` ทุกชั้นไว้แล้วตั้งแต่ 2026-09-23)
3. **bundle ของหน้าแอดมิน** — **หน้าแอดมินเป็นไฟล์สาธารณะ** การล็อกอินเกิดในเบราว์เซอร์
   แล้วค่อยเอา token ไปยิง API ⇒ อะไรที่ `import` เข้าไปในโค้ด `frontend/` จะไปโผล่ที่
   `https://<โดเมน>/assets/xxxxx.js` ให้ใครก็ได้โหลดโดยไม่ต้องล็อกอิน

**นี่คือเหตุผลที่ราคาถูกคิดที่เซิร์ฟเวอร์** (`POST /api/admin/pricing/quote`) ไม่ใช่ส่งสมุดราคา
ไปให้เบราว์เซอร์คิดเองเหมือนหน้าเดโมใน `mockup/` — เบราว์เซอร์เห็นแค่ผลของรหัสที่ตัวเองพิมพ์
สมุดราคาไม่เคยออกจากเครื่องเลยสักครั้ง

⇒ **ห้ามส่ง `models[x].cells` / `adders` / `base` ออกไปทาง API ให้ผู้เรียกที่ไม่ได้เป็นคนเอาเข้ามา**

## แอดมินแก้ราคาเองจากหน้าจอ (2026-09-21)

**เจ้าของสั่งว่าแอดมินไม่ได้มารันสคริปต์** ⇒ ปุ่มสองปุ่มบนหัวหน้า "สมุดราคา" คือทางแก้ราคาของแอดมิน
(เดิมอยู่บนหน้า "คิดราคาสินค้า" · ย้ายเมื่อ 2026-09-23 — ดูหัวข้อ "สองหน้า สองสิทธิ์" ข้างล่าง)
(CLI เหลือไว้บูตเล่มแรกเท่านั้น) · คู่มือสำหรับแอดมินอยู่ที่ `docs/guide-pricebook-admin.md`

| ปุ่ม | เส้น API | ทำอะไร |
| --- | --- | --- |
| ดาวน์โหลดแม่แบบราคา | `GET /api/admin/pricebook/template` | สมุดเล่มที่ใช้อยู่ → `.xlsx` ที่แก้แล้วอัปกลับได้ |
| อัปโหลดราคาใหม่ (ขั้นตรวจ) | `POST /import/preview` | อ่านไฟล์ → บอกว่าช่องไหนจะเปลี่ยน · **ไม่เขียนอะไรเลย** |
| อัปโหลดราคาใหม่ (ขั้นบันทึก) | `POST /import/apply` | รวม **เฉพาะรุ่นที่ติ๊ก** ลงเล่มปัจจุบัน |
| ย้อนไปเล่มก่อนหน้า | `POST /rollback` | ยกเล่มของการบันทึกครั้งก่อนกลับมาใช้ — **เป็นการบันทึกใหม่** ย้อนผิดก็ย้อนกลับได้ |

**สี่ข้อที่เป็นกติกา ไม่ใช่รายละเอียดการเขียน** (เจ้าของเคาะทั้งสี่ · `services/pricingLab/bookUpdate.ts`):

1. **บันทึก = รวมรายรุ่น ไม่ใช่เขียนทับทั้งเล่ม** — จอเขียนว่า "รุ่นที่ไม่ติ๊ก = คงราคาเดิม"
2. **รุ่นที่ไม่มีในไฟล์ ห้ามลบ** — แม่แบบที่แอดมินถือมาอาจเก่ากว่าเล่มปัจจุบัน
3. **จอโชว์ 3 เล่มล่าสุดให้ย้อน** — ตั้งแต่ 2026-09-23 ประวัติอยู่ในฐานครบทุกครั้งตลอดไป (≤ 75 KB ต่อการอัป
   ทั้งเล่ม · เจ้าของเคาะ) และ **โค้ดไม่มี UPDATE/DELETE ของตารางประวัติ** (`diag:pricing-db` ข้อ 13 grep ให้)
4. **สิทธิ์ = `page.pricebook`** (เดิมใช้ `page.pricing` ร่วมกับหน้าคิดราคา · แยกเมื่อ 2026-09-23) · สิ่งที่ทำให้ปลอดภัย
   คือ **ขั้นตรวจที่บันทึกอะไรไม่ได้** คั่นอยู่ก่อนเสมอ ไม่ใช่ตัวด่านสิทธิ์
   ⇒ ใครถอดขั้นตรวจออกเพื่อ "ให้เร็วขึ้น" คือคนที่ถอดด่านเดียวของฟีเจอร์นี้ทิ้ง

### สองหน้า สองสิทธิ์ (2026-09-23)

เจ้าของสั่ง: **"หน้าคิดราคาก็คือคิดราคาอย่างเดียว"** — ก่อนหน้านี้ใครเปิดหน้าคิดราคาได้ก็แก้ราคาได้ทั้งเล่ม

| หน้า | API | ด่าน | มีอะไร |
| --- | --- | --- | --- |
| คำนวณราคา | `/api/admin/pricing` — `GET /overview` · `POST /quote` **แค่สองเส้น** | `page.pricing` | ช่องพิมพ์รหัส · ผลคิดราคา · ปุ่ม ＋ เพิ่ม (โผล่เฉพาะคนที่มี `page.pricebook`) |
| สมุดราคา | `/api/admin/pricebook` — ที่เหลือทั้งหมด | `page.pricebook` | ปุ่มไปหน้าคำนวณราคา (โผล่เฉพาะคนที่มี `page.pricing`) · เล่มที่ใช้อยู่ + ย้อน · แม่แบบ · ตารางรุ่น + แก้ทีละรุ่น · รหัสย่อย |

⚠️ **เส้นที่เขียนหรือคืนราคาเกิน "ผลของรหัสที่พิมพ์" ห้ามอยู่ใน `pricingLabRouter`** — `diag:role-permissions`
อ่านซอร์สมาเทียบว่าฝั่งคิดราคามีแค่สองเส้นข้างบน เพิ่มเส้นที่สามเมื่อไหร่ด่านล้ม

ตารางรุ่นมีสองคอลัมน์ที่ต้องรู้ที่มา:
- **ชื่อรุ่น** มาจาก `displayName()` (`labels.ts`) — รวมชื่ออื่นที่ต่างแค่เลขรุ่น `BH-01`+`BH-02` → `BH-01,02`
  ให้ตรงกับซีรีส์ในหน้าข้อมูลสินค้า · **รหัสในฐานยังเป็น `BH-01`** (ประวัติราคาผูกกับรหัสนั้น)
- **สินค้าที่ครอบ** มาจาก `bookCoverage.ts` — นับ `products.model` ที่หัวรหัสตกรุ่นนั้นด้วย `modelOfCode()`
  (ด่านเดียวกับที่ `parseProductCode` ใช้หารุ่น · ตรงกันครบ 22,298 รหัส วัด 2026-09-23 · 0.2 วิ เทียบกับ
  9.8 วิ ถ้าใช้ตัวอ่านเต็ม) · จำไว้ 10 นาทีต่อเล่ม · **ไม่เท่ากับจำนวนในหน้าข้อมูลสินค้า** โดยตั้งใจ
  (BH-01 = 1,522 เพราะรวมซีรีส์ `Heater (สั่งในประเทศ)` 269 รายการที่หัวรหัสเป็น BH-01)

### แก้ทีละรุ่นจากหน้าจอ (2026-09-23)

เจ้าของสั่งเพิ่ม: **ต้องแก้ราคาและกฎของรุ่นเดียวได้จากจอ ไม่ต้องดาวน์โหลด Excel ออกไปแก้**
(เคาะหน้าตาจาก mockup ชุด `pe-*` เมื่อ 2026-09-22/23 · รอบนี้ทำซีรีส์ BH ก่อน)

| เส้น API | ทำอะไร |
| --- | --- |
| `GET /model/:code` | ทุกอย่างของรุ่นเดียวที่จอต้องใช้ + คำศัพท์ให้ช่องเลือก (`modelEditor.ts`) |
| `PUT /model/:code` | รวมรุ่นนั้นลงเล่มปัจจุบัน (เขียนแถวเดียว) · มี `fingerprint` กันสองคนแก้ทับกันแบบเดียวกับ `/import/apply` |

**`fingerprint` = `r<เลขการบันทึก>` และต้องส่งมาทุกครั้งที่บันทึก** (ไม่ส่ง = 400 · ไม่ใช่หัวเล่ม = 409 ข้อความเดิม)
— ด่านจริงคือ `UNIQUE NULLS NOT DISTINCT (parent_id)` ของ `pricing_book_revisions` ⇒ ฐานเป็นคนตัดสิน
สองคนที่กดพร้อมกันจากเล่มเดียวกันจะผ่านได้คนเดียวเสมอ (ยุคไฟล์ตรวจแล้ว `await` อ่านไฟล์ก่อนเขียน
อีก request แทรกได้ และไม่ส่ง `fingerprint` ก็ข้ามด่านไปเลย) · token ยังเป็น **ระดับเล่ม** —
ใครบันทึกรุ่นไหนก็ตาม คนที่เปิดหน้าค้างไว้จะโดน 409

**สามอย่างที่จอนี้ตั้งใจไม่ให้แก้** และเหตุผลอยู่ที่หัว `modelEditor.ts`:
สูตร `derivedDims` · ข้อความ/เงื่อนไขของ `constraints` (แก้ได้แค่เปิด-ปิด) · เงื่อนไขแบบพิมพ์เอง
⇒ ช่อง "คิดเมื่อไหร่" เป็นรายการปิดจาก `labels.ts` และ **ฝั่งรับประกอบเงื่อนไขขึ้นใหม่เอง**
ไม่ใช่ `JSON.parse` แล้วยัดลงสมุด เพราะหน้าจอไม่ใช่ด่าน

⚠️ **`over` / `step` ที่ว่าง ไม่ใช่ 0 และไม่ใช่ 1** — engine อ่านว่า `over = standard[dim]`
เผลอเติม `?? 0` ให้ `over` ตอนรับจากจอเมื่อไหร่ กฎอย่าง "สายยาวเกิน 30 CM" จะคิดเงินตั้งแต่
เซนติเมตรแรก ⇒ ทุกใบแพงขึ้น 120 บาทโดยไม่มีอะไรฟ้อง (เจอจาก `diag:pricing-model-edit` 2026-09-23)


**สามเรื่องที่เจอหลังเจ้าของเปิดซีรีส์ TS จริง (2026-09-23) — กติกาแล้ว ไม่ใช่แค่บั๊กที่แก้ไปแล้ว**
- **ช่องราคาแยกตามค่าแกนที่ลบเลขทิ้ง = "ไม่มีราคา" ไม่ใช่ 0** — เดิมหน้าจอส่ง 0 ⇒ ขนาดนั้นกลายเป็นไม่คิดเงินเพิ่ม
  เงียบ ๆ · ตอนนี้ค่านั้นหายจากตาราง แล้วตัวคิดราคาตอบ "ไม่มีราคาสำหรับ…" (`diag:pricing` หัวข้อ 4)
- **เงื่อนไขประกอบจากชีต (`all`/`any`/`not` · `axis`+`in`/`notIn`) ต้องบันทึกผ่าน** — เดิม `readWhen` ปฏิเสธ
  ⇒ หน้า TS-18 บันทึกไม่ได้เลยสักครั้ง · ยังเป็นไวยากรณ์ปิด ทุกใบชี้คำในรายการปิด ลึกไม่เกิน 4 ชั้น
- **บันทึกโดยไม่แตะอะไร ต้องได้สมุดเท่าเดิมทุกค่า ทุกรุ่น** (`diag:pricing` หัวข้อ 5 ไล่ครบ 13 รุ่น) —
  ลำดับกฎคงตามชีต · ลำดับคีย์ของช่วงราคาเท่าตัวนำเข้า · หน่วยที่มีช่องว่างนำ (`" m"`) ไม่ถูกตัด

### สมุดรายชีต — 1 ชีต Excel = 1 หน้า (2026-09-24)

เจ้าของเห็นหน้าแก้ทีละรุ่นของซีรีส์ TS แล้วบอกว่า **"งงกว่าเดิม · ให้ใกล้เคียง format เดิมใน excel มากที่สุด ·
เริ่มที่ชีท TS-01+TS-01-0 ก่อน · 1 ชีท / 1 สมุด"** ⇒ ตารางหน้าสมุดราคาเป็น 1 แถวต่อ 1 ชีต (`PriceModel.sheet`)
และชีตที่พร้อมเปิดเป็น `SheetEditor.tsx`: หัว "ราคาตั้ง Standard TS_-01" → ตาราง แถว × คอลัมน์ ตามลำดับในชีต →
แถบหมายเหตุราคาสายใต้ตาราง

| เส้น API | ทำอะไร |
| --- | --- |
| `GET /sheet/:sheet` | ทุกรุ่นของชีต (`modelEditorView` ต่อรุ่น — ตารางสองแกนได้ `rows`/`cols`/`cells` มาด้วย) |
| `PUT /sheet/:sheet` | `{ fingerprint, models: { รหัส: { cells, adderRates } } }` → **การบันทึกครั้งเดียว** ทุกรุ่นในชีต (`applySheetEdit`) |

- **ชีตไหนได้หน้าแบบ Excel** ตัดสินที่ `excelReady()` ที่เดียว: ตารางสองแกน + กฎทุกข้อเป็นราคาแยกตามแกนที่ไม่ใช่แกนของตาราง
  ไม่มีเงื่อนไข + ไม่มีข้อจำกัด/ตัวเลือกท้ายรหัส/สูตร — **ทุกอย่างที่รุ่นมีต้องมีที่อยู่บนจอนั้น** ไม่งั้นจอดูครบทั้งที่มีกฎซ่อน
  (วันนี้ผ่าน 2 รุ่น = ชีต TS-01+TS-01-0 · `diag:pricing` หัวข้อ 6 ล็อกไว้) — ชีตอื่นขยายเกณฑ์ทีละแบบ
- `cells` รับเฉพาะช่องในตาราง แถว × คอลัมน์ ที่มีอยู่ · `null` = ลบช่อง (ไม่รับผลิต ไม่ใช่ 0) · **ลำดับคีย์เดิมคงที่**
  ช่องที่เพิ่งกรอกต่อท้าย ⇒ บันทึกเปล่าได้ JSON เดิมทุกไบต์ · แถวที่ว่างทั้งแถวในชีต (7TN ของ TS-04) ไม่มีในคีย์ ⇒ ไม่โผล่
- `adderRates` แก้ได้เฉพาะค่าแกนที่สมุดรู้จัก (`knownRateKeys`) — รุ่นแบบ Excel รู้จักชนิดสายจากทุกกฎที่แยกตามชนิดสายในเล่ม
  ⇒ ช่องที่ลบทิ้งยังกรอกคืนได้ · **รุ่นอื่นรู้จักแค่คีย์ของตัวเอง** (ลองขยายแล้ว กฎเคลือบเทฟลอนได้ช่องว่างเพิ่ม 32 ช่อง)
  · **ทุกรุ่นรู้จักค่าที่แถวรหัสย่อย `setAxis` ครอบรุ่นนั้นตั้งได้ด้วย** (2026-09-25) — สาย C/TS ของ TS_-01 มาจากแคตตาล็อก
  ไม่มีในชีต ⇒ เดิมไม่มีช่องให้กรอก · route ของหน้าแก้จึงใช้ `editorBook()` (เล่ม + รหัสย่อยจากฐาน) ตอนแสดง/ตรวจ
  แต่ **บันทึกด้วยเล่มเดิม** — ส่งเล่มที่รวมแล้วไป `commitBookChange` = แถวรหัสย่อยถูกคัดลอกลงสมุด กลายเป็นสองที่ต้องแก้คู่กัน
  · **การรวมทั้งเล่มข้ามรุ่นที่แกนนั้นเป็นแกนของตารางราคาตั้ง** (2026-09-25) — ขนาดแกน D ของ TS-06 (36 ค่า) คือขนาดที่ TS-06 ทำ
  ไม่ใช่ของใช้ร่วม ⇒ กฎความยาวแกนของ TS_-01 มีแค่ช่อง 4.8 · 6 · คีย์ที่เป็นเลขล้วนเรียงตามค่า (JS วาง "6" ก่อน "4.8")
- **กฎบวกเพิ่มที่แยกราคาตามแกนซึ่งไม่อยู่ในตารางราคาตั้ง** (TS_-01 `len_l1` byAxis `D`) — `readTsGeneric` จำ `D` จากรหัส
  เมื่อค่านั้นเป็นคีย์ของกฎ · ค่าที่อ่านไม่ออกลง `cfg.unread.D` ⇒ ขึ้น "ยังไม่รวม" ไม่ใช่ "รหัสไม่ได้บอก"
  · ไม่มี `x` = ไม่มี `dims.L1` ⇒ engine ข้ามกฎเอง ไม่ต้องรู้ D · แมปอ่านอัตราข้ามชีตได้เฉพาะบางแถวด้วย `ratesFrom.keys`
- เพิ่มกฎใหม่ในแมปแล้ว เล่มในฐานเติมด้วย `importer.ts --data <dir> --new-rules [--apply]` — เติมเฉพาะ id ที่ยังไม่มี
  (+ `standard` ของมิตินั้น) ไม่แก้กฎ/ราคาเดิม ⇒ ราคาที่แก้จากจอ (TS 160) ไม่หาย · `DEPLOY.md` 4.11ข
- ⚠️ **ทดสอบเส้นที่บันทึกกับฐานจริง ห้ามเดาเลข fingerprint ว่า "เก่า"** — 2026-09-24 ใช้ `r1` ทดสอบ 409 แล้วบังเอิญเป็นเล่มปัจจุบัน
  ราคาถูกบันทึกจริง (r2 · ย้อนด้วย r3 ภายในไม่กี่นาที เล่มกลับเท่า r1 ทุกไบต์) ⇒ ใช้ข้อความที่ไม่มีทางเป็น token เช่น `not-a-token`
  และพิสูจน์ทางบันทึกที่ `diag:pricing-db` หัวข้อ 12ข (ROLLBACK) แทน

**ของรอบตารางในไฟล์ราคา (2026-09-24)** — เจ้าของขอให้หน้าชีตมีสามอย่างที่ไฟล์เขียน/ระบายรอบตารางด้วย แล้วเจอว่าหนึ่งในนั้นคือราคา:

  `TSJ-01 4.8+2M` ไม่ได้ ⇒ ชี้คอลัมน์นี้ว่า *"มันก็บอกอยู่แล้วนี้ไงครับ เรื่องสาย"* · ชนิดสายผูกกับ TYPE ⇒ รหัสที่ไม่บอกชนิดสายใช้ค่านี้
  (รหัสที่บอกเองชนะ · ชนะ `axisDefaults` ที่ตั้งได้ค่าเดียวต่อรุ่น) · บรรทัดค่าสายเขียนบอกว่าใช้สายไหน "เพราะรหัสไม่ได้ระบุ"
  · ⚠️ **ต่อมาวันเดียวกันเจ้าของส่งแคตตาล็อกมาแล้วเคาะให้ยึดภาพ** ⇒ ค่าในกลไกนี้เป็น **สแตนเลสถักทุก TYPE** แล้ว

    (ในนั้น 516 อ่านได้ครบทุกท่อน · ที่เหลือมี `-S###`/ความยาวแกนขึ้นแดง) · ตัวเลข 711 ที่เคยรายงานผิด
- ตัวหนังสือแดงใต้คอลัมน์ (`*M8x1.25`) · คอลัมน์พื้นเหลือง (1/4” · M5) = `PriceModel.layout` — **แสดงผลอย่างเดียว engine ไม่อ่าน**

  `axisDefaultsBy` · ชื่อ/ที่มาของกฎ id เดิม — **ไม่แตะตัวเลขราคา** · `DEPLOY.md` ขั้น 4.11ข)

## ที่ยังไม่ได้ทำ (ตั้งใจ)

* **ยังไม่ต่อกับใบเสนอราคา** — ต้องเคาะก่อนว่าราคาขั้นต่ำของสินค้าสั่งทำคิดยังไง และของ
  configured เข้า Odoo ทางไหน (แผนเฟส D ใน `docs/plan-pricing-subcodes.md`)
* **สมุดราคามี 13 รุ่นจาก 11 ชีต** (`BH-01C` ย้ายไปเป็นตัวเลือกของ `BH-01` แล้ว) — วัด 2026-09-23: ครอบคลุมรหัสจริง 80.1% จาก 22,296
  (เฟส C เสร็จแล้ว) ⇒ รหัสที่เหลืออีกราว 1 ใน 5 ยังได้ "ไม่มีสมุดราคาของรุ่นนี้"
  ชีตที่ยังไม่ได้ลอกไล่ดูได้จาก `npm run diag:pricing-coverage` ซึ่งเรียงให้ว่ารุ่นไหนคุ้มที่สุด
* **ตารางรหัสย่อยมีแถวเดียวที่มีหลักฐาน** (`-U` ของ TS-14 ซึ่งชีตเขียนไว้ในรหัสมาตรฐานของตัวเอง)
  ที่เหลือว่างไว้รอคำตอบจากฝ่ายขาย — **ห้ามเดา** เพราะพอตั้งค่าแล้ว รหัสอื่นทุกตัวที่มี
  ตัวอักษรนั้นจะคิดตามทันที และราคาที่ผิดจะดูเหมือนราคาที่ถูกทุกประการ
