แอดมินพิมพ์รหัสสินค้าสั่งทำ (`TSK-14 6x200+150-BU`) แล้วได้ราคาพร้อมที่มาของทุกบาท ·
ตัวอักษรที่ระบบยังไม่รู้จักมีปุ่มให้ตั้งค่าเองตรงนั้น ไม่ต้องรอแก้โปรแกรม

**เจ้าของสั่ง 2026-09-18:** เอาของที่ทำไว้เข้าหน้าแอดมินจริง เพื่อให้คนที่ล็อกอินแล้ว
เท่านั้นเข้าไปทดลองใช้ได้ — **เฟสแรกยังไม่ต่อกับใบเสนอราคา คิดราคาให้ดูอย่างเดียว**
และต้องถอดออก/แก้เพิ่มได้ทุกเมื่อระหว่างที่ดีไซน์ยังไม่นิ่ง

**เจ้าของสั่ง 2026-09-21:** เลิกทำงานใน `prototypes/` — หน้า "คิดราคาสินค้า" มีจริงแล้ว
⇒ โฟลเดอร์นั้นถูกลบทิ้งทั้งก้อน ของที่ยังจำเป็นย้ายมาอยู่ในระบบจริงทั้งหมด:
`scripts/pricebook/` (เครื่องมือของสมุดราคา) · `scripts/diag/pricing*.ts` (ด่าน) · โฟลเดอร์นี้ (ตัวคิดราคา)
— หน้าเดโม HTML ชุดเก่าถูกลบทิ้ง เพราะหน้าแอดมินแทนมันได้ครบแล้ว

## สมุดราคาอยู่ที่ไหน และทำไมต้องคิดที่เซิร์ฟเวอร์

`pricebook/book.json` — **git-ignore ไว้** เพราะเป็นราคาจริงของบริษัททั้งเล่ม
⇒ `git pull` บนเซิร์ฟเวอร์ไม่ได้ไฟล์นี้ไปด้วย ต้องคัดลอกขึ้นไปเอง:

```bash
# บนเครื่อง dev (ที่มีไฟล์ Excel ใน data/)
npm run pricebook:import                        # → pricebook/book.json (เขียนที่นี่ที่เดียว)
npm run diag:pricing && npm run diag:pricing-coverage
scp pricebook/book.json PMSV:~/chatbot/pricebook/book.json
```

**เครื่องมืออื่นของสมุดราคา (`scripts/pricebook/`):**

```bash
npm run pricebook:xlsx -- export              # แม่แบบกฎราคา .xlsx (แก้แล้วนำกลับเข้าได้)
npm run pricebook:xlsx -- odoo                # ตารางราคาสำหรับนำเข้า Odoo (ทางเดียว)
npm run pricebook:xlsx -- import "<ไฟล์>.xlsx" [--save]
npm run pricebook:calc -- --code "TSK-04(S2)6x300+3M"   # ลองคิดราคาจากบรรทัดคำสั่ง
npm run pricebook:calc -- --subcodes
```

ตัวนำเข้าอ่านไฟล์ Excel ผ่าน **ไฟล์ map เขียนมือ** ใน `scripts/pricebook/maps/` — หนึ่งไฟล์
ต่อหนึ่งตารางราคา บอกว่าตารางอยู่เซลล์ไหน **ไม่ใช้ auto-detect โดยตั้งใจ** เพราะ 30 ชีตวางหัวตาราง
คนละแบบ ⇒ เดาผิดเงียบ ๆ แล้วไม่มีใครรู้จนของหลุดถึงลูกค้า

### สามที่ที่ห้ามวางสมุดราคา — ทั้งสามถูกเสิร์ฟออกเว็บโดยไม่มีการตรวจสิทธิ์

1. **`public/`** — `express.static` ที่ `index.ts`
2. **`data/`** — `express.static('/data')` ที่ `index.ts` (ไฟล์ `.xlsx` ต้นทางก็ห้ามไปไว้ที่นั่น
   ด้วยเหตุผลเดียวกัน — ตอนนี้ `.gitignore` กัน `data/*.xlsx` ไว้แล้ว)
3. **bundle ของหน้าแอดมิน** — **หน้าแอดมินเป็นไฟล์สาธารณะ** การล็อกอินเกิดในเบราว์เซอร์
   แล้วค่อยเอา token ไปยิง API ⇒ อะไรที่ `import` เข้าไปในโค้ด `frontend/` จะไปโผล่ที่
   `https://<โดเมน>/assets/xxxxx.js` ให้ใครก็ได้โหลดโดยไม่ต้องล็อกอิน

**นี่คือเหตุผลที่ราคาถูกคิดที่เซิร์ฟเวอร์** (`POST /api/admin/pricing/quote`) ไม่ใช่ส่งสมุดราคา
ไปให้เบราว์เซอร์คิดเองเหมือนหน้าเดโมใน `mockup/` — เบราว์เซอร์เห็นแค่ผลของรหัสที่ตัวเองพิมพ์
สมุดราคาไม่เคยออกจากเครื่องเลยสักครั้ง

⇒ **ห้ามส่ง `models[x].cells` / `adders` / `base` ออกไปทาง API ให้ผู้เรียกที่ไม่ได้เป็นคนเอาเข้ามา**

## แอดมินแก้ราคาเองจากหน้าจอ (2026-09-21)

**เจ้าของสั่งว่าแอดมินไม่ได้มารันสคริปต์** ⇒ ปุ่มสองปุ่มบนหัวหน้า "คิดราคาสินค้า" ทำแทน `scp`
กับ `npm run pricebook:import` ทั้งหมด · คู่มือสำหรับแอดมินอยู่ที่ `docs/guide-pricebook-admin.md`

| ปุ่ม | เส้น API | ทำอะไร |
| --- | --- | --- |
| ดาวน์โหลดแม่แบบราคา | `GET /template` | สมุดเล่มที่ใช้อยู่ → `.xlsx` ที่แก้แล้วอัปกลับได้ |
| อัปโหลดราคาใหม่ (ขั้นตรวจ) | `POST /import/preview` | อ่านไฟล์ → บอกว่าช่องไหนจะเปลี่ยน · **ไม่เขียนอะไรเลย** |
| อัปโหลดราคาใหม่ (ขั้นบันทึก) | `POST /import/apply` | รวม **เฉพาะรุ่นที่ติ๊ก** ลงเล่มปัจจุบัน |
| ย้อนไปเล่มก่อนหน้า | `POST /rollback` | ยกเล่มสำรองกลับมาใช้ (เล่มที่ใช้อยู่กลายเป็นสำรอง) |

**สี่ข้อที่เป็นกติกา ไม่ใช่รายละเอียดการเขียน** (เจ้าของเคาะทั้งสี่ · `services/pricingLab/bookUpdate.ts`):

1. **บันทึก = รวมรายรุ่น ไม่ใช่เขียนทับทั้งเล่ม** — จอเขียนว่า "รุ่นที่ไม่ติ๊ก = คงราคาเดิม"
2. **รุ่นที่ไม่มีในไฟล์ ห้ามลบ** — แม่แบบที่แอดมินถือมาอาจเก่ากว่าเล่มปัจจุบัน
3. **เก็บเล่มเก่า 3 เล่ม** ที่ `pricebook/backups/` — อยู่ใต้ `/pricebook/` ที่ git-ignore ไว้แล้ว
   ⇒ **ห้ามย้ายออกไปไว้ที่อื่น** มันคือราคาจริงเหมือนกันทุกไบต์
4. **สิทธิ์ใช้ `page.pricing` เดิม ไม่มีช่องใหม่** — ใครเปิดหน้านี้ได้ก็กดได้ · สิ่งที่ทำให้ปลอดภัย
   คือ **ขั้นตรวจที่บันทึกอะไรไม่ได้** คั่นอยู่ก่อนเสมอ ไม่ใช่ตัวด่านสิทธิ์
   ⇒ ใครถอดขั้นตรวจออกเพื่อ "ให้เร็วขึ้น" คือคนที่ถอดด่านเดียวของฟีเจอร์นี้ทิ้ง

`data/` กับ `npm run pricebook:import` **ยังอยู่และยังใช้ได้** — แต่ตั้งแต่วันนี้มันคือทางสำหรับ
**ลอกชีตใหม่เข้ามา** (งานของ dev) ส่วน **ไฟล์ที่อัปผ่านจอคือตัวจริงของราคา** (งานของแอดมิน)
⇒ รัน `pricebook:import` ทับเมื่อไหร่ ราคาที่แอดมินแก้ผ่านจอหายทั้งหมด **ตั้งใจให้เป็นแบบนั้น**
เพราะมันคือการเริ่มเล่มใหม่จากชีตต้นทาง ไม่ใช่การแก้ราคา

## ไฟล์ในโฟลเดอร์นี้

| ไฟล์ | หน้าที่ |
| --- | --- |
| `types.ts` | ชนิดข้อมูลกลาง — สมุดราคาเป็น "ข้อมูล" ไม่ใช่โค้ดต่อรุ่น |
| `engine.ts` | `computePrice()` — pure function ห้าม import DB/network/LLM |
| `code.ts` | `parseProductCode()` — "รหัสที่คนพิมพ์ → สเปก" ไม่คิดเงินเอง |
| `subcodes.ts` | จับคู่รหัสย่อย: **แคบชนะกว้าง · ตรงตัวชนะแม่แบบ** |
| `bookStore.ts` | อ่าน `pricebook/book.json` + รวมรหัสย่อยจากตาราง (**ของในฐานชนะ**) |
| `bookFile.ts` | แม่แบบ .xlsx ตอนมีคนกดปุ่มบนจอ — ปั้นไฟล์ออก · อ่านไฟล์ที่อัปเข้ามาจาก buffer |
| `bookUpdate.ts` | เทียบสมุดสองเล่ม · **รวมเฉพาะรุ่นที่ติ๊ก** · เก็บเล่มเก่า 3 เล่ม · ย้อนกลับ |
| `subcode-census.json` | รหัสย่อยไหนเจอบ่อยแค่ไหนในรหัสจริง 22,061 รหัส — หน้าจอใช้เรียงว่าควรตั้งตัวไหนก่อน (ภาพนิ่ง ไม่ต่อฐานตอนรัน) |

**ด่านของโมดูลนี้อยู่ใน `scripts/diag/`** ซึ่ง `import` ตัวจริงจากที่นี่
⇒ แก้โค้ดตรงนี้แล้วด่านเห็นทันที ไม่ใช่ด่านที่เฝ้าสำเนาที่ตายแล้ว:

| ด่าน | ถามว่าอะไร | ต้องมี server ไหม |
| --- | --- | --- |
| `npm run diag:pricing` | รวม 4 ตัว: `pricingLab.ts` (แถวในตาราง → ราคาขยับ) · `pricingGolden.ts` (62 เคส — เฉลยที่ฝ่ายขายเขียนไว้ในชีตเอง) · `pricingRoundtrip.ts` (26 — ส่งออก .xlsx → อ่านกลับ → ราคาต้องเท่าเดิมทุกบาท) · `pricingImport.ts` (26 — ปุ่มนำเข้า/ส่งออกบนหน้าจอ) | ไม่ต้อง (แต่เขียนฐานจริงแล้วลบทิ้ง) |
| `npm run diag:pricing-coverage` | **รหัสจริงในฐานกี่ % ที่รุ่นของมันมีตารางราคาแล้ว** (ด่านของเฟส C) | ไม่ต้อง (อ่าน `products` อย่างเดียว) |
| `npm run diag:pb-ui` | **เปิดหน้าจริงแล้วกดปุ่มจริง** — ดาวน์โหลดแม่แบบ → อัปกลับ → ติ๊กรุ่น → บันทึก → ย้อนเล่ม ที่ 1280px และ 390px | **ต้องมี** (`PORT=3098 npm run dev`) |

⚠️ **`diag:pb-ui` เขียนทับ `pricebook/book.json` ของ cwd ที่เซิร์ฟเวอร์รันอยู่** (แล้วกดย้อนคืนให้
ตอนจบ) ⇒ รันกับเซิร์ฟเวอร์ที่เปิดจาก **worktree ของงาน** เท่านั้น ห้ามรันบน PMSV

**อีกสองด่านอยู่ใน `mockup/` ซึ่ง git-ignore ไว้** (เหตุผลเดียวกับ `mockup/_verify-pack.mjs`
ของหน้าเดโม — มันต้องมี server รันอยู่ และเซ็น JWT เองจาก `JWT_SECRET` จึงไม่ควรเดินทางออกไปกับรีโป):

## ที่ยังไม่ได้ทำ (ตั้งใจ)

* **ยังไม่ต่อกับใบเสนอราคา** — ต้องเคาะก่อนว่าราคาขั้นต่ำของสินค้าสั่งทำคิดยังไง และของ
  configured เข้า Odoo ทางไหน (แผนเฟส D ใน `docs/plan-pricing-subcodes.md`)
* **สมุดราคามี 14 รุ่นจาก 11 ชีต** — วัด 2026-09-21: ครอบคลุมรหัสจริง 80.1% จาก 22,286
  (เฟส C เสร็จแล้ว) ⇒ รหัสที่เหลืออีกราว 1 ใน 5 ยังได้ "ไม่มีสมุดราคาของรุ่นนี้"
  ชีตที่ยังไม่ได้ลอกไล่ดูได้จาก `npm run diag:pricing-coverage` ซึ่งเรียงให้ว่ารุ่นไหนคุ้มที่สุด
* **ตารางรหัสย่อยมีแถวเดียวที่มีหลักฐาน** (`-U` ของ TS-14 ซึ่งชีตเขียนไว้ในรหัสมาตรฐานของตัวเอง)
  ที่เหลือว่างไว้รอคำตอบจากฝ่ายขาย — **ห้ามเดา** เพราะพอตั้งค่าแล้ว รหัสอื่นทุกตัวที่มี
  ตัวอักษรนั้นจะคิดตามทันที และราคาที่ผิดจะดูเหมือนราคาที่ถูกทุกประการ
