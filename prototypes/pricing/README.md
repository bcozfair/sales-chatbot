# Prototype — เครื่องคิดราคาแบบ configurator

**ของทดลอง ยังไม่ต่อกับระบบจริง** สร้างเพื่อพิสูจน์ว่าไฟล์ราคา Excel ของฝ่ายขาย
(`data/ราคา BH (Final 02-02-69).xlsx` · `data/ราคาTC อัพเดต (13-05-69).xlsx`)
แปลงเป็นเครื่องคิดราคาอัตโนมัติได้จริง **ก่อน** ที่จะไปแตะอะไรใน production

---

## ข้อตกลงของโฟลเดอร์นี้

1. **ไม่มีไฟล์ไหนใน `prototypes/` ถูก import จากโค้ดที่รันจริง** ตรวจได้ด้วย
   `grep -rn "prototypes/" --include=*.ts --include=*.html . | grep -v "^./prototypes/"`
   ต้องได้ 0 บรรทัด
2. **ไม่แตะฐานข้อมูล ไม่มี migration ไม่มี route ไม่มี LLM** — `engine.ts` ไม่มี import ของ
   สิ่งเหล่านี้เลยแม้แต่ตัวเดียว ตัวที่อ่านไฟล์คือ `importer.ts` ซึ่งอ่าน `.xlsx` อย่างเดียว
3. **`utils/pricing.ts` · `services/quotationService.ts` · `index.ts` ไม่ถูกแก้แม้แต่บรรทัดเดียว**
4. ถอดทั้งโฟลเดอร์ทิ้งแล้วระบบเดิมเหมือนเดิมเป๊ะ

---

## วิธีเปิดดู (สำหรับเอาไปพรีเซนต์)

หน้าเดโมเป็นไฟล์ HTML **ไฟล์เดียวจบ** ดับเบิลคลิกเปิดได้เลย ไม่ต้องรัน server ไม่ต้องมี node:

```
prototypes/pricing/demo/index.html
```

สร้างใหม่เมื่อสมุดราคาเปลี่ยน: `node prototypes/pricing/demo/build.mjs`

หน้านี้ฝัง `engine.ts` **ตัวเดียวกับที่รันในเครื่อง** (ผ่าน esbuild ตอน build) ไม่ได้เขียน JS ขึ้นใหม่
ตัวเลขทุกตัวในหน้า — รวมถึงผลด่านตรวจ 11 เคส — **คำนวณสดตอนเปิดหน้า** ไม่ใช่ตัวเลขที่พิมพ์ลงไป
⇒ ถ้าวันหนึ่ง engine คิดผิด หน้านี้จะขึ้นกากบาทให้เห็นเอง ไม่ใช่โชว์ ✓ ค้างไว้

## วิธีรัน

```bash
# 1. แปลง Excel → สมุดราคา JSON  (ต้องมีไฟล์ xlsx ใน data/)
npx tsx prototypes/pricing/importer.ts

# 2. ด่านตรวจ — เทียบกับ "ตัวอย่างการคิดราคา" ที่ฝ่ายขายเขียนไว้ในชีตเอง
npx tsx prototypes/pricing/golden.ts

# 3. ลองคิดราคาด้วยมือ
npx tsx prototypes/pricing/cli.ts --list
npx tsx prototypes/pricing/cli.ts TSK-04 --options D
npx tsx prototypes/pricing/cli.ts TSK-04 --axis D=6 --axis "thread=1/2”" --dim L1=300
npx tsx prototypes/pricing/cli.ts BH-01C --dim dia_mm=600 --dim width_mm=150 --opt conn:pl2
```

`importer.ts` รับ `--data <path>` ถ้าไฟล์ Excel ไม่ได้อยู่ที่ `data/` ของทรีนี้
(ไฟล์ xlsx ยังไม่ถูก commit จึงไม่ตามไป worktree เอง)

## สิ่งที่ prototype นี้ค้นพบ (ไม่ได้ตั้งใจหา)

### 1. ⚠️ ตัวอย่างใน TS-18 ไม่ตรงกับตารางของตัวเอง — ห้ามใช้เป็นเฉลย

ชีตเขียนไว้ที่ `TS-18!L4`:

```
เช่น  TSK-18(2) 6-6x100+50 = 800+650+(5x25) = 1525
```

- `800 + 650 + 125 = 1,575` **ไม่ใช่ 1,525** — ตัวเลขในหมายเหตุบวกกันเองยังไม่ลงตัว
- ราคาตั้ง D=6 Type K/J ในตารางปัจจุบัน (`TS-18!D25`) = **880 ไม่ใช่ 800**

⇒ หมายเหตุนี้ค้างมาจากราคารอบก่อน ตารางถูกอัปเดตแต่ตัวอย่างไม่ถูกอัปเดตตาม
**ถ้าใครเอาไปเป็น golden test จะไล่แก้ engine ให้ตรงกับราคาที่เลิกใช้แล้ว**
`golden.ts` จึงพิมพ์เคสนี้ออกมาเป็น "รายงาน" ไม่ใช่ "ด่าน"

### 2. ⚠️ กับดัก regex ที่เกือบทำให้ทุกขนาดได้ราคาต่ำสุด

ตัวแยกช่วงราคาของ BH เขียนครั้งแรกว่า `/^(\d+)\s*-\s*\D/` เพื่อจับ `"101 - ขึ้นไป"`
แต่ `\s*` backtrack ให้ `\D` ไปแมตช์ช่องว่างได้ ⇒ `"0 - 5"` ถูกอ่านเป็น **ช่วงไม่มีขอบบน**
แล้วกลืนทุกขนาดไปที่ 700 บาท (ของจริงคือ 10,975) แก้เป็น `[^\d\s]`

จับได้เพราะ golden case มีเฉลยจากชีต — ถ้าไม่มีเฉลย บั๊กแบบนี้ **ไม่ error และไม่มีอะไรฟ้อง**
มันแค่คืนราคาถูกเกินจริงไปเรื่อย ๆ

### 3. adder ผูกกับ "ช่วงราคา" ไม่ใช่ผูกกับรุ่น

BH-03 คิดค่ากำลังไฟเกิน 100W ที่ 10 บาท/100W (`G3:G7`) แต่ **`G8` ของช่วง "101 ขึ้นไป" เว้นว่าง**
⇒ สินค้าที่ตกช่วงนั้นไม่คิดค่ากำลังไฟ ถ้าเขียนเป็น "รุ่น BH-03 คิด 10 บาท/100W" จะเกินจริง
1,900 บาทในเคสตัวอย่าง (2000W)

### 4. หน้าแปลน JIS 10K ราคาไม่เท่ากันข้ามชีต

`TS-18` → 1/2"+3/4" 580 · 1" 650 · 1.5" 650 · 2" 700
`TW` → 1/2"+3/4" 600 · 1" 800 · 1.5" 910 · 2" 1,100

**ห้ามทำตาราง "ราคาหน้าแปลนกลาง"** — adder ต้อง scope ที่รุ่น

## สิ่งที่ prototype นี้ **ยังไม่ได้** ทำ

จงใจไม่ทำ เพราะเป็นของที่ต้องตัดสินใจก่อน ไม่ใช่ของที่เดาแล้วแก้ทีหลังได้ถูก

| ยังไม่มี | ทำไม |
| --- | --- |
| ตารางใน DB · migration · หน้าจอแอดมิน | ต้องรู้ก่อนว่าใครแก้สมุดราคาได้ และแก้ผ่าน import ไฟล์ใหม่หรือแก้ในหน้าจอ |
| ต่อเข้า `item_details` / snapshot | ข้ามไปแล้วถอยไม่ได้ (ใบเก่าจะอ่านไม่ออก) — ต้องเคลียร์คำถามเรื่อง `minimum_sales_price` ก่อน |
| ราคาขั้นต่ำของของ configured | ไม่มีแถวใน `products` ⇒ กฎ `MIN_PRICE` และคิว `price_approval` มองไม่เห็นเลย ต้องถามหัวหน้าว่าคิดจากอะไร |
| `odoo_manual_review` | ของ configured ไม่มีใน product master ของ Odoo ⇒ ต้องกันออกจากไฟล์ export |
| parse รหัสรุ่นจากข้อความ (`TSK-18(2) 6-6x100+50`) | ต้องมีก่อนถึงจะต่อเข้าเส้น LINE ได้ · เฟสแรกควรทำผ่าน UI ที่มีให้เลือก |
| 24 ชีตที่เหลือของ TC | ชีตที่ทำแล้ว (TS-04 · TS-14 · TS-18 · BH) ครอบคลุม primitive ครบทั้ง 5 แบบแล้ว |

## ข้อจำกัดที่รู้ตัว (ของ prototype นี้เอง)

1. **ภาษาเงื่อนไขยังไม่มีตัวดำเนินการ modulo** ⇒ กฎ "ความกว้างควรลงท้ายด้วย 0 หรือ 5"
   (`BH!H5`) ยังใส่ไม่ได้ · ทางแก้: เพิ่ม operator หรือย้ายกฎนี้ไปเป็น validation ของ UI

2. **กฎที่ต้องรู้ "ความหมายเชิงตัวเลข" ของแกน D ยังต้องไล่ระบุค่าเป็นรายตัว**
   เช่น "2 element ทำได้ตั้งแต่แกน 6 mm ขึ้นไป" ตอนนี้เขียนเป็น
   `{ axis: "D", in: ["2","2.5S","3","3A", … ] }` ซึ่งยาวและลืมง่าย
   **ตัว prototype ยืนยันข้อเสนอเดิมว่า ค่าแกนควรเก็บเป็น string ดิบ แล้วแขวน `tags`
   (เช่น `dia_mm: 6`, `grade: "finished_core"`) เป็น attribute เสริม** ไม่ใช่ parse
   ความหมายจากตัวอักษร (`3.2A` · `15.97B` · `21.3I` · `7TN` ไม่มีกติกาเดียวที่ครอบคลุม)

3. **BH: ยังไม่ชัดว่า `600x150` ในรหัสรุ่นคือ (เส้นผ่านศูนย์กลาง × ความกว้าง) หรือกลับกัน**
   สูตร `W × π × ID / 645` เป็นการคูณ ผลลัพธ์จึงเท่ากันทั้งสองทาง ราคาเลยไม่เพี้ยน
   **แต่กฎ "OD เล็กสุด 65mm" กับ "ความกว้างเล็กสุด 25mm" ผูกกับตัวที่ถูก** — ต้องถามฝ่ายผลิต

4. **`TS-18` ใช้แกน `flange` ตัวเดียวกับสองตาราง (เฟอร์รูล/JIS)** ซึ่งวันนี้ไม่ชนกัน
   เพราะป้ายกำกับคนละแบบ แต่เป็นความบังเอิญ ไม่ใช่สัญญา — ของจริงควรแยกเป็น
   `flange_type` + `flange_size`

5. **สมุดราคายังไม่มีเวอร์ชันที่ผูกกับวันที่มีผล** — `book.version` เป็นวันที่ import
   ไม่ใช่วันที่ราคาเริ่มใช้

## แผนที่ไฟล์

| ไฟล์ | หน้าที่ |
| --- | --- |
| `types.ts` | ชนิดข้อมูลกลาง — ทุกอย่างที่ต่างกันรายรุ่นเป็น "ข้อมูล" ไม่ใช่โค้ด |
| `engine.ts` | **pure function** คิดราคา + คืน breakdown · ห้ามมี DB/network ในไฟล์นี้ |
| `importer.ts` | `.xlsx` + ไฟล์ map → `book.json` · อ่าน cached result ไม่ประเมินสูตรเอง |
| `maps/*.map.json` | บอกว่าตารางของแต่ละชีตอยู่เซลล์ไหน — เขียนมือโดยตั้งใจ ไม่ auto-detect |
| `golden.ts` | ด่านตรวจ เทียบกับตัวอย่างที่ฝ่ายขายเขียนไว้ในชีต |
| `cli.ts` | ลองคิดราคาด้วยมือ |
| `book.json` | ผลลัพธ์ของ importer (สร้างใหม่ได้ตลอด) |

**เส้นเชื่อมที่ตั้งใจให้คม:** engine คืน *ราคาตั้งต่อหน่วย* แล้วจบ ส่วนลด / VAT / โปรโมชัน /
MOQ / blacklist / เครดิต เป็นของท่อเดิมทั้งหมด `utils/pricing.ts` จึงไม่ต้องแก้แม้แต่บรรทัดเดียว
